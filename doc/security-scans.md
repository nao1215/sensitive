# Security scans

`gosec.yml` follows nao1215/markdown's workflow name and file name and runs gosec with tests across the root, tests and all three adapter modules. `trivy.yml` scans the entire filesystem, including every go.mod/go.sum, on pushes, pull requests and a daily schedule, and uploads SARIF to GitHub code scanning. Both fail on findings. Only the SARIF job gets `security-events: write`; checkout does not persist credentials.

Fork PR tokens have reduced permissions, but code scanning has a specific upload exception for `pull_request` runs, as documented in [GitHub's upload-permission troubleshooting guide](https://docs.github.com/en/enterprise-cloud%40latest/code-security/reference/code-scanning/troubleshoot-analysis-errors/resource-not-accessible). Keep the ordinary `pull_request` event and its SARIF upload; do not switch to `pull_request_target` or hide scan/upload failures with continue-on-error.

On 2026-11-15, the [Trivy incident advisory](https://github.com/aquasecurity/trivy/security/advisories/GHSA-69fq-xp46-6x23) identified trivy-action versions before v0.35.0, setup-trivy before the restored v0.2.6, and specific compromised Trivy releases/images. We selected the subsequent [trivy-action v0.36.0 release](https://github.com/aquasecurity/trivy-action/releases/tag/v0.36.0), commit `ed142fd0673e97e23eac54620cfb913e5ce36c25`, and the [Trivy v0.76.2 security release](https://github.com/aquasecurity/trivy/releases/tag/v0.76.2). The composite action pins its nested setup-trivy v0.2.6 and cache actions to full commits. The selected releases fall outside the affected ranges; this does not claim that any future tool execution is risk-free.

The [gosec security advisories](https://github.com/securego/gosec/security/advisories) listed no published advisories at review time. We reviewed [v2.30.0 release notes](https://github.com/securego/gosec/releases/tag/v2.30.0) and the action source: the tag still points to a v2.29.0 image. We use the same post-release commit as markdown, `14c713478ed40c9bdfa56d35d9c2142b91608106`, whose action pins the v2.30.0 image by SHA256. This is a reviewed post-release commit, not the v2.30.0 tag commit.

Local gosec v2.30.0 findings in synthetic credential tests are individually justified with `#nosec` comments: published fake AWS/Stripe fixtures must remain recognizable to exercise detection; fixed-seed random tests are not cryptography; an IntN(256) conversion cannot overflow a byte; the panic subprocess runs this test binary; file reads use fixed local globs; comparison benchmarks intentionally marshal synthetic passwords before masking. No production rule is disabled globally. Trivy found CVE-2026-39824 in the zerolog adapter's golang.org/x/sys v0.29.0 dependency, which was updated to v0.50.0. Re-run scans when dependencies or fixtures change.

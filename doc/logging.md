# Masking slog output

Pass a downstream handler and an explicit scanner to `NewSlogHandler`. Messages, attribute keys, group names and values are scanned before forwarding. Group-qualified keys are also checked as TextHandler writes them (`group.key`). The [runnable Examples](../example_test.go) show text and JSON output; [structured Examples](../example_test.go) show the shared JSON policy.

## Keep the logger's JSON shape

Nested fields such as `user.id`, `order.amount` and `error.code` remain queryable by Loki, Datadog, CloudWatch and BigQuery. Objects stay objects, arrays stay arrays, and clean numeric values keep their number type and precision, so existing field filters and range queries continue to work.

| Value | Forwarded representation |
|---|---|
| Clean string or scalar | Original scalar type |
| Sensitive string | Only sensitive spans replaced |
| Sensitive numeric value | Marker string, preserving the existing detector contract |
| Matching sensitive key or group | Entire value replaced with `[REDACTED]` |
| Group | Sanitized names and recursively sanitized values |
| LogValuer | Resolved value, then sanitized; at most 100 resolutions |
| Any | Encoded JSON with masked leaves and keys, forwarded as raw JSON |
| []byte and named byte slices | Contents scanned before base64 encoding; sensitive contents become masked text |
| error, including wrapped errors | Scanned `Error()` text, never an empty JSON object |

Scalars and errors use the original attribute key as detector context, including values resolved by LogValuer and attached by WithAttrs. Duration is checked as both nanoseconds and duration text; float values use both JSON decimal/exponent encoding and text encoding; time values use both RFC3339Nano and the TextHandler millisecond layout. A match in either representation prevents the original typed value from reaching either handler.

JSON numbers with fractions or exponents, including json.Number, are also scanned as their exact integer value when one exists; a detection replaces the whole numeric lexeme. Expansion is bounded and never rounds through float64.

The Any path uses `encoding/json` before masking, as `slog.JSONHandler` does. JSON tags, `json:"-"`, `omitempty`, custom `MarshalJSON`, and unexported-field visibility therefore retain their normal behavior. A `fmt.Stringer` does not override JSON encoding. Nested `LogValuer` methods are not called by `encoding/json`, as they are not called by an unwrapped JSONHandler; their exported JSON fields are scanned instead. Nested `Secret` values mask themselves through `MarshalJSON`. TextHandler displays structured Any values as compact JSON text, with its normal quoting; errors remain readable text.

The shared engine validates the whole document with `encoding/json.Valid`, then walks its values, decodes escaped strings with `encoding/json`, and retains the original numeric lexemes (the precision guarantee of `UseNumber`). This avoids materializing a map tree and preserves duplicate keys and their order. Profiling found Decoder.Token to be an allocation hot spot, so the validated byte walk replaces the original token walker; JSON semantics are checked differentially against encoding/json by FuzzJSONShape. All values under duplicate keys are visited. Masked keys can collide, so consumers must not interpret the result as an authorization policy or a lossless identifier mapping. The same engine protects the encoded output of the [zap, zerolog and logrus adapters](adapters.md), and `Scanner.MaskJSON` sanitizes API responses, audit exports and support bundles outside logging. This returns bytes, not a copy of the original Go type.

## One key policy

By default, the values of `password`, `passwd`, `secret`, `token`, `api_key`, `authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `access_token`, `refresh_token`, `id_token`, `x-api-key`, `DB_PASSWORD`, `Private-Token`, `client_secret`, `auth_token` and `PGPASSWORD` are hidden, including whole objects, arrays, booleans and nulls. Matching ignores ASCII case and `_`, `-`, `.` and space: `apiKey` and `API-KEY` match `api_key`. Match names as they appear after JSON encoding; a struct field renamed by a JSON tag uses the JSON name. Names added with WithSensitiveKeys match exactly after this normalization. The defaults also match a name whose last separator or camel-case segment is password, passwd, secret, token, credential or auth, or key after an api, secret, private, access or account segment, so `POSTGRES_PASSWORD` and `X-Auth-Token` match while `primary_key` and `token_count` do not.

`WithSensitiveKeys(names...)` adds names to that set, and repeated options add to each other. `WithoutDefaultSensitiveKeys()` drops the default names and the suffix rule, leaving only the added names; with none, whole-value key masking is off. The options copy the configured names and their order does not matter. A matching `WithGroup` replaces the whole group with a marker and suppresses its descendant attributes; attributes attached before that group remain intact. See the [runnable option Example](../example_test.go).

Whole-value key replacement applies to structured fields and groups. Credential assignments in raw `Scanner.Scan` text also use WithSensitiveKeys when KindCredential is selected: `WithSensitiveKeys("recovery")` recognizes `recovery=opaque`. Raw scanning returns byte spans; Go fmt slice values are scanned as a complete credential container. Provider-specific labels and URL/DSN credentials retain their detector rules. Existing `embargotest.Expect` can compare captured JSON with `scanner.MaskJSON` to enforce the identical policy; `WithScanner` alone checks detector findings. See the [application output regression](../tests/comparison_test.go).

## Why a Handler, rather than another ReplaceAttr

`ReplaceAttr` is convenient when an application already configures HandlerOptions, and those options can still be set on the downstream handler. However, slog does not pass group attributes through ReplaceAttr, and its `groups` argument cannot rename group names. A Handler can freeze sanitized `WithAttrs` values, sanitize messages and keys, suppress sensitive groups, and return a fixed error when normalization fails. A second callback API would offer weaker guarantees under a similar name, so embargo keeps one Handler API.

Attributes passed through `With` are sanitized and frozen at that call. Handle checks its context before work, between detectors and scalar scans, and before forwarding; cancellation replaces the record with a diagnostic. An already running detector or user marshaler cannot be interrupted. With has no context parameter, so its eager work cannot observe a later record context. Successful records preserve context, timestamp, level and source metadata. Downstream ReplaceAttr callbacks and custom handlers can introduce new data after embargo; test the actual sink when using them.

## Bounds and failures

Each encoded Any document is limited to 1 MiB input/output, depth 64 and 4 MiB cumulative detector input, including repeated key context. Explicit slog groups and WithGroup chains share depth 64. Each scalar scan is bounded to 4 MiB, but scalar record attributes have no record-wide byte limit. Encoded logger writers include the newline in their 1 MiB retained-input and masked-output limits. Oversized plain byte slices in slog are rejected before base64 encoding because their encoded size is known.

These limits bound already encoded input, retained output and cooperative scanner work. They do not bound the input reader, the total Go object graph, or allocations and time inside MarshalJSON, LogValue, String and Error. encoding/json.Encoder constructs a complete value before calling its writer, so a writer that refuses oversized writes cannot stop that encoder or a user method midway. Use Secret or a LogValuer that returns a bounded value for expensive or untrusted types. Input decoding has no byte limit; bound its upstream reader. Recorder WithMaxBytes bounds total retained sink bytes and WithTimeout each Run child process, not in-process encoding methods.

Invalid JSON, cycles, unsupported values, scanner/normalization panics, exhausted size/depth limits and context cancellation produce a fresh diagnostic record. It preserves the timestamp and level and replaces the message with one of `embargo: record withheld (masking error)`, `embargo: record withheld (size limit)` or `embargo: record withheld (canceled)`. Its only attribute is the integer `withheld_attributes`. It contains no original message, key, value, group or source location; WithAttrs and WithGroup attachments made through the embargo handler are also withheld. Attributes bound to the downstream handler before it was wrapped are outside embargo, so they appear unmasked in both normal and diagnostic records; wrap the sink handler first and bind attributes on the result. The count includes record and bound attributes, counting a group or container as one attribute without resolving its contents.

Ordinary slog.Logger calls discard Handler errors but still deliver this diagnostic. Direct Handler.Handle callers also receive the existing fixed sanitization error; a downstream failure is returned or joined with it. No failure-observer option is needed: monitor the fixed diagnostic message and count at the sink. A sink that fails or independently suppresses records cannot be made durable by this wrapper.

HTTP and gRPC access hooks keep the request context for masking. Only requests already canceled when the access record is built get context.WithoutCancel plus a 100 ms timeout. Ordinary requests have no extra deadline imposed by embargo, and cancellation during masking still withholds request content. A failed access record retains HTTP status or gRPC code and elapsed handler duration alongside time, level, the fixed reason and withheld_attributes; no method, target, header, metadata or error text survives. The budget and clock have an internal injection seam for deterministic tests, without adding a public configuration API. Diagnostic forwarding detaches an expired context. Cooperative checks cannot interrupt a running detector, formatter or downstream write. Service results remain unchanged.

HTTP logs decoded query keys and values without re-encoding; query values receive their original key as context. Each original value is masked once and the completed access record is sent directly to the downstream handler. The same policy covers Location headers. Masking already masked text with several detector kinds can remove more because replacement shortens context distances; general Mask/MaskJSON calls and independently stacked hooks do not promise cross-kind idempotence. A wrapped HTTP panic before a final response logs status 0 and response_written=false, then propagates unchanged, including http.ErrAbortHandler. If a final status was already written it is preserved; a normal return without an explicit write logs the implicit 200. Duration excludes masking work.

Zap and zerolog accept bytes, without a context. On invalid or oversized events they emit a JSON diagnostic and continue at the next newline, retaining at most 1 MiB of input. Oversized events are counted without buffering their contents. Diagnostics retain only recognized `level` enum strings. Byte writers cannot authenticate the encoder configuration or distinguish an encoder timestamp from a user field with the same name, so they omit all input time fields, including `time`, `ts` and `timestamp`; validating a number or RFC3339 string is not proof of origin. This also prevents oversized or console-formatted user fields from being copied into the diagnostic. The message key is `message` when that standard key was observed, otherwise `msg`. Counts exclude standard time, level and message fields; incomplete/malformed input counts only observed attribute keys. Flush/Close emit a diagnostic for a pending fragment and return a fixed framing error. Sink failures remain sticky.

Logrus returns a successful formatted diagnostic after normalization failures so its logger actually writes it. OTel exporters replace each failed record independently, keeping other sanitized batch records. Failed log resource/scope fields are replaced by an empty resource and the fixed `embargo` scope using the SDK. Log diagnostics explicitly copy the original TraceID, SpanID and TraceFlags, including zero values, regardless of the export context. Their isolated provider reserves one attribute slot for withheld_attributes independently of environment limits. Failed spans keep structural trace/span IDs without TraceState, SDK loss counts, time and status code, omit events/links/resource/scope and replace the name with the diagnostic message. Their counts include record, resource, scope, event and link attributes. Sentry preserves timestamp/level, generates a fresh event ID and emits only the fixed message and `contexts.embargo.withheld_attributes`, counting tag, context, breadcrumb data and dynamic sampling attributes. None of these counts recursively visits user values. OTel and logrus report successful delivery when their diagnostic was accepted, avoiding retries of an already delivered fallback; exporter/sink errors retain the existing fixed error boundary.

## Joined paths and number spellings

When a finding crosses a dot between group or key segments, the JSON walker and slog handler mask every segment in that joined path. This includes bound WithAttrs/WithGroup chains and nested objects or arrays; unrelated complete keys are first masked independently. The TextHandler cannot retain a visible email prefix while replacing only its last segment. Frozen bound values are replayed without calling user formatters again.

JSON number spellings are compared as exact integers without float rounding, including optional minus signs, fractions and signed exponents. When the integer is detected, the entire lexeme becomes a marker string. Numeric strings follow the same rule because some logging encoders serialize json.Number as a quoted string. Invalid JSON numbers with leading zeros are rejected as JSON input.

Standard zap console encoders emit tab-delimited level tokens, with an optional timestamp first. Byte-writer fallback keeps a recognized level from those first two columns, including uppercase levels. An encoder configured without a level writes none, so the fallback cannot invent one. Arbitrary console text or custom level encodings do not become trusted metadata; only fixed level enums can survive.
